CHAPTER 9 • WEB TECHNOLOGY

Authentication, Authorization, and Web Security

Understand how websites verify users, control access to information, and protect online systems from common security threats.

1. Introduction to Web Security

Web security refers to the practices, technologies, and procedures used to protect websites, web applications, servers, and user information from unauthorized access, misuse, damage, and other online threats.

Whenever people log in, submit forms, make online transactions, or share personal information, security measures help protect their accounts and data.

The CIA Triad

The CIA Triad is a basic model used to explain three important goals of information security.

Confidentiality

Ensures that information is available only to authorized people. Example: protecting a student's grades from public access.

Integrity

Ensures that information remains accurate and is not changed without permission.

Availability

Ensures that systems and information are accessible when authorized users need them.

Why It Matters

These three principles work together to build trust and support reliable online services.

Key Idea

Web security is not only about preventing attacks. It also involves protecting user privacy, maintaining accurate information, and keeping services dependable.

2. Authentication

Authentication is the process of verifying the identity of a person, device, or system. It answers the question: Who are you?

For example, when a student signs in to a school portal using a username and password, the system checks whether the submitted credentials match the account's stored authentication information.

How Authentication Works

  1. The user opens a website or application and chooses to sign in.
  2. The user provides an identity claim, such as a username or email address, and an authentication factor.
  3. The system securely checks the submitted information.
  4. If the information is valid, the system establishes an authenticated session or issues a secure token.
  5. If the information is invalid, access is not granted.

Example

A student enters an email address and password on a learning management system. The system verifies the credentials before allowing the student to open their account.

3. Types of Authentication

Authentication methods use one or more factors to verify identity. Different systems choose methods based on their security needs.

Password-Based Authentication

Uses a secret password or passphrase known by the account holder.

Two-Factor Authentication (2FA)

Requires two different verification factors, such as a password and a one-time code.

Multi-Factor Authentication (MFA)

Uses two or more independent factors to provide additional identity verification.

Biometric Authentication

Uses physical or behavioral characteristics, such as fingerprints or facial recognition.

Token-Based Authentication

Uses a digital token issued after successful authentication.

Single Sign-On (SSO)

Allows a user to access multiple related applications through one trusted sign-in process.

Authentication Factors

  • Something you know: A password or PIN.
  • Something you have: A registered device or security key.
  • Something you are: A biometric characteristic, such as a fingerprint.
Using more than one independent factor can make account access more secure than relying on a password alone.

4. Authorization

Authorization is the process of determining what an authenticated user is allowed to view, use, or change. It answers the question: What are you allowed to do?

After a user signs in, the application checks the user's permissions before allowing access to protected pages, records, or actions.

How Authorization Works

  1. The user is authenticated by the application.
  2. The system identifies the user's role or assigned permissions.
  3. The user requests a resource or action.
  4. The system checks the applicable access rules.
  5. Access is allowed or denied based on those rules.

Administrator

May manage accounts, update system settings, and access administrative features.

Teacher

May view class lists, record grades, and manage learning materials for assigned classes.

Student

May view personal grades, schedules, and learning materials, but cannot change another student's records.

Guest

May view public information but cannot access private account information.

Important

Being successfully signed in does not mean a user has permission to access every feature. Authorization limits access according to approved rules.

5. Types of Authorization and Access Control

Access control models define how systems decide who can access particular resources.

Role-Based Access Control (RBAC)

Permissions are assigned to roles, and users receive permissions through their assigned roles.

Attribute-Based Access Control (ABAC)

Access decisions are based on attributes such as the user's department, resource type, or time.

Discretionary Access Control (DAC)

The owner of a resource can decide which other users may access it and what permissions they receive.

Mandatory Access Control (MAC)

Access is controlled by a central policy using assigned security levels or classifications.

Choosing an Access Control Model

The appropriate model depends on the organization's needs, the sensitivity of its information, and how permissions should be managed. A school portal may use RBAC for common student, teacher, and administrator permissions.

6. Authentication vs. Authorization

Authentication and authorization are related security processes, but they have different purposes.

Basis Authentication Authorization
Main Question Who are you? What are you allowed to do?
Purpose Verifies identity. Checks permissions.
When It Happens Usually before access to an account is granted. After identity is established, when a resource or action is requested.
Example Signing in with a username and password. Allowing a teacher to record grades but not change system-wide settings.

Remember the Difference

Authentication verifies the user. Authorization determines the user's permitted actions. A secure application needs both.

7. Common Web Security Threats

Web applications may face different threats. Understanding them helps developers create safer systems and helps users make informed decisions online.

Threat 01

Phishing

A deceptive message or website attempts to trick people into revealing sensitive information.

Threat 02

SQL Injection

A vulnerability that can occur when an application handles database input unsafely. Developers reduce this risk by using parameterized queries.

Threat 03

Cross-Site Scripting (XSS)

Can occur when untrusted content is included in a webpage without proper handling. Output encoding helps prevent it.

Threat 04

Cross-Site Request Forgery (CSRF)

Can cause a signed-in browser to send an unwanted request to a website. Anti-CSRF tokens help protect applications.

Threat 05

Denial-of-Service (DoS)

Attempts to make a service unavailable by overwhelming its resources. Monitoring and rate limits can improve resilience.

Safe Learning Reminder

Study security threats to understand how to recognize, prevent, and report them. Only test systems when you have clear permission from the system owner.

8. Web Security Best Practices

Developers and website administrators should apply security throughout the development and maintenance of a web application.

Use HTTPS and TLS

Protect data while it travels between a user's browser and the website server.

Store Passwords Securely

Store passwords using a dedicated password-hashing algorithm with unique salts. Never store plain-text passwords.

Enable MFA

Offer multi-factor authentication for accounts, especially those with access to sensitive information.

Validate Input

Check data on the server and use safe database queries and output encoding.

Protect Sessions

Use secure session settings, expire inactive sessions, and avoid exposing session identifiers.

Update Software

Apply trusted updates and security patches to frameworks, libraries, servers, and applications.

Back Up Important Data

Maintain protected backups and periodically check that data can be restored.

Apply Least Privilege

Give users and application components only the permissions needed to perform their tasks.

For Everyday Users

  • Use strong, unique passwords for different accounts.
  • Do not share passwords or verification codes.
  • Be careful with unexpected links and attachments.
  • Sign out when using a shared computer.
  • Report suspicious activity to the appropriate support team.

10. Glossary

Term Definition
AuthenticationThe process of verifying a user's or system's identity.
AuthorizationThe process of deciding what an authenticated user is permitted to access or do.
Access ControlRules and mechanisms that determine who can use specific resources.
EncryptionThe process of transforming information so it cannot be understood without the proper key.
HTTPSThe secure version of HTTP that uses encryption through TLS.
MFAMulti-Factor Authentication; identity verification using multiple independent factors.
SessionA period of interaction between a user and an application.
TokenA digital value used to represent or prove an authenticated state or permission.
PhishingA deceptive attempt to obtain sensitive information by pretending to be trustworthy.
VulnerabilityA weakness that could affect the security of a system.
