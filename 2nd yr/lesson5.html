PAGE 01INTRODUCTION

Introduction to User Interface Design and Accessibility

Every website, mobile application, and digital platform has an interface that allows people to interact with its features. Users depend on menus, buttons, links, forms, icons, images, and text to understand information and complete tasks.

User Interface (UI) Design focuses on arranging and presenting these elements in a clear and useful way. Accessibility ensures that people with different abilities can perceive, understand, navigate, and interact with digital content.

A successful website should not only look attractive. It should also be understandable, easy to use, consistent, and available to as many people as possible.

PAGE 03UI FUNDAMENTALS

What is User Interface Design?

A User Interface (UI) is the part of a digital product that a person sees and interacts with. It includes the visible screens, menus, buttons, links, forms, icons, images, text, and other controls.

User Interface Design is the process of arranging and styling these elements so people can complete tasks easily and confidently.

Examples of User Interfaces

A good interface helps users understand what they can do, where they are, and what will happen when they take an action.

PAGE 04UI AND UX

Understanding UI and UX

User Interface (UI) and User Experience (UX) are connected concepts, but they have different focuses.

User Interface (UI)

Focuses on the visible and interactive elements of a digital product.

  • Buttons and menus
  • Colors and typography
  • Page layout
  • Icons and visual controls

User Experience (UX)

Focuses on the overall experience a person has while using a product.

  • Ease of use
  • Task completion
  • Efficiency
  • User satisfaction

A website may have attractive colors and buttons but still provide a poor experience if users cannot find information or complete a task. Good UI supports a positive UX.

Remember: UI is about the interface people interact with. UX is about the overall experience they have.
PAGE 05DESIGN PRINCIPLES

Core Principles of Effective UI Design

Effective interface design follows principles that help users understand and interact with a digital product.

1. Clarity

Use understandable labels, familiar icons, and straightforward instructions.

2. Consistency

Keep colors, typography, spacing, buttons, and navigation patterns consistent.

3. Visual Hierarchy

Make important information stand out through size, position, contrast, and spacing.

4. Feedback

Show users that an action was received, such as a success message after submitting a form.

5. Simplicity

Remove unnecessary elements and avoid overwhelming users with too many choices.

6. Efficiency

Help users complete common tasks with as few unnecessary steps as possible.

7. Error Prevention and Recovery

Prevent avoidable mistakes and explain how users can correct errors.

PAGE 06CLARITY AND CONSISTENCY

Clarity and Consistency

Clarity

Clarity means making interface elements easy to recognize and understand. Labels should describe their purpose. Instructions should use familiar words and avoid unnecessary technical language.

Consistency

Consistency means using the same design patterns throughout a website. If buttons use the same color and shape for similar actions, users can learn how the interface works.

Consistent Button Design

Example: Similar buttons use consistent styling and clear action labels.

Inconsistent labels, colors, and navigation can confuse users. A consistent design reduces the effort needed to learn a website.

PAGE 07VISUAL HIERARCHY

Visual Hierarchy

Visual hierarchy is the arrangement of interface elements according to their importance. It guides the user's attention and helps them identify what to read or do first.

Designers create hierarchy through font size, font weight, color contrast, spacing, alignment, and position.

PAGE 08FEEDBACK AND SIMPLICITY

Feedback, Simplicity, and Efficiency

Feedback informs users about the result of an action. Examples include confirmation messages, loading indicators, and error notices.

Simplicity means showing only the information and controls needed for the current task. Too many unnecessary elements can distract users.

Efficiency helps users complete tasks with fewer steps and less confusion.

PAGE 10NAVIGATION AND BUTTONS

Navigation Menus and Buttons

Navigation menus help users understand the structure of a website and move between its pages. Navigation labels should be short, descriptive, and familiar.

Buttons trigger actions. Their labels should clearly explain what happens when users activate them.

Good Navigation Practices

  • Place main navigation in a predictable location.
  • Use meaningful link names.
  • Show which page or section is currently active.
  • Make navigation usable with a keyboard.
  • Avoid hiding essential links behind unclear icons.

Forms, Search Boxes, and Cards

Forms collect information such as names, email addresses, feedback, and registration details. Every input should have a clear label and helpful instructions.

Search boxes allow users to find specific information without browsing every page. Cards group related information into organized sections.

PAGE 12WEB ACCESSIBILITY

Introduction to Web Accessibility

Web accessibility means designing and developing websites so people with different abilities can perceive, understand, navigate, and interact with them.

Accessibility also benefits people using small screens, slow connections, older devices, or experiencing temporary limitations such as a broken arm or a bright environment.

Accessibility Supports Different Users

⌨️Keyboard usersNavigate without a mouse
🔊Screen reader usersListen to page information
🔎Low-vision usersEnlarge and read content
💬Deaf usersUse captions and transcripts
Important: Accessibility is part of good web design—not an optional decoration.
PAGE 13ACCESSIBILITY BARRIERS

Common Accessibility Barriers

A barrier is a design or technical issue that makes it difficult or impossible for someone to use a website.

  • Missing image descriptions: A blind user may not understand informative images without meaningful alternative text.
  • Poor contrast: A user with low vision may struggle to read text that blends into its background.
  • Mouse-only controls: A person who cannot use a mouse may be unable to reach buttons or links.
  • Missing captions: Deaf or hard-of-hearing users may miss information in videos.
  • Complex instructions: Users with cognitive or learning disabilities may struggle with unclear language and unpredictable navigation.
Removing barriers makes websites more inclusive and improves usability for everyone.
PAGE 14ASSISTIVE TECHNOLOGY

Assistive Technology

Assistive technology includes software and hardware that help people interact with digital content. Accessible websites should work with these tools whenever possible.

🔊

⌨️

Keyboard Navigation

Allows people to operate websites without a mouse.

🔍

🎙️

Speech Recognition

Allows users to control devices or enter text using voice commands.

Developers can improve compatibility by using semantic HTML, descriptive labels, and logical page structure.

PAGE 15POUR PRINCIPLES

The Four POUR Principles

The Web Content Accessibility Guidelines (WCAG) organize accessibility around four principles. They are commonly remembered as POUR.

P

Perceivable

Information must be presented in ways users can perceive.

O

Operable

Interface controls and navigation must be usable.

U

Understandable

Information and operation must be clear and predictable.

R

Robust

Content should work reliably with browsers and assistive technologies.

These principles provide a foundation for evaluating and improving website accessibility.

PAGE 16PERCEIVABLE

Principle 1: Perceivable

Perceivable means that users must be able to access the information presented on a webpage through at least one suitable way.

Practical Examples

  • Add meaningful alternative text to informative images.
  • Provide captions for videos with audio.
  • Use readable text and sufficient color contrast.
  • Do not communicate important information through color alone.
  • Make content adaptable to different display settings.

PAGE 17OPERABLE

Principle 2: Operable

Operable means users must be able to interact with controls and navigate the website. All essential functions should be available without requiring a mouse.

Practical Examples

  • Allow users to reach links and buttons using the Tab key.
  • Use Enter or Space to activate controls where appropriate.
  • Show a visible keyboard focus indicator.
  • Keep the focus order logical.
  • Do not trap keyboard users inside a component.
TabShift + TabEnterSpace

Keyboard testing helps identify controls that cannot be reached or activated without a mouse.

PAGE 18UNDERSTANDABLE

Principle 3: Understandable

Understandable means that information and interface behavior should be clear, consistent, and predictable.

Practical Examples

  • Use plain and familiar language.
  • Keep menus and navigation patterns consistent.
  • Provide clear instructions for forms.
  • Identify errors using text and explain how to fix them.
  • Use descriptive headings and link labels.

PAGE 19ROBUST

Principle 4: Robust

Robust means website content should work reliably with different browsers, devices, and assistive technologies.

How to Support Robust Content

  • Use valid HTML markup.
  • Choose semantic elements that describe their purpose.
  • Use appropriate labels for form controls.
  • Provide accessible names for interactive elements.
  • Test pages using different browsers and assistive technologies.

    Open Student Portal
</button>

<label for="student-email">
    Email Address
</label>
<input type="email" id="student-email">

Native HTML elements provide built-in behavior that helps browsers and assistive technologies interpret the page.

PAGE 20WCAG CONFORMANCE

WCAG Conformance Levels

The Web Content Accessibility Guidelines (WCAG) provide internationally recognized recommendations for making web content more accessible.

WCAG defines three conformance levels:

A

Level A

Minimum level of accessibility requirements.

AA

Level AA

Addresses a broader range of barriers and is a common target for organizations.

AAA

Level AAA

Highest level, which may not be achievable for every type of content.

The appropriate target depends on applicable laws, policies, and project requirements.

WCAG provides guidance for evaluating accessibility. It does not replace real user testing.
PAGE 21READABILITY

Text, Headings, and Readability

Readable content helps users understand information without unnecessary effort. Text should be organized, legible, and easy to follow.

Recommended Practices

  • Use one clear page title followed by descriptive section headings.
  • Maintain a logical heading order.
  • Choose readable fonts.
  • Provide enough line spacing and paragraph spacing.
  • Write concise link text that explains its destination.
  • Allow users to zoom text without losing content or functionality.

PAGE 22COLOR AND CONTRAST

Color and Contrast

Color contrast is the difference in brightness between foreground content and its background. Sufficient contrast makes text and controls easier to see.

WCAG 2.2 Level AA generally requires a contrast ratio of at least 4.5:1 for normal text and 3:1 for large text.

Do Not Rely on Color Alone

For example, do not identify required fields only by making them red. Add a written indicator such as “Required” so users can understand the information without depending on color.

PAGE 23IMAGES AND ALT TEXT

Images and Alternative Text

Alternative text, commonly called alt text, is a text description added to an image. It communicates the purpose or important information of an informative image to users who may not see it.

Example of Meaningful Alt Text

<img
  src="campus-library.jpg"
  alt="Students reading at the campus library"
>

Decorative Images

Decorative images generally use an empty alt attribute so screen readers can skip them.

<img src="decoration.png" alt="">
Describe the image's purpose or important information. Avoid unnecessary descriptions that do not help users understand the content.
PAGE 24KEYBOARD ACCESSIBILITY

Keyboard Accessibility

Some users navigate websites without a mouse. They may use a keyboard, switch device, or other input method. Essential interface features must therefore be keyboard accessible.

Important Keyboard Actions

  • Tab: Moves focus forward to the next interactive element.
  • Shift + Tab: Moves focus backward.
  • Enter: Activates links and buttons where appropriate.
  • Space: Activates buttons and controls where appropriate.
  • Arrow keys: Navigate within some grouped controls.
button:focus-visible,
a:focus-visible,
input:focus-visible {
    outline: 3px solid #10569a;
    outline-offset: 3px;
}

A visible focus indicator helps keyboard users identify the currently focused element.

PAGE 25ACCESSIBLE FORMS

Forms and Error Messages

Accessible forms provide clear labels, useful instructions, and helpful error messages. Users should understand what information is expected before submitting a form.

Form Accessibility Practices

  • Connect every input with a visible label.
  • Explain the expected format before submission.
  • Identify errors in text.
  • Explain what went wrong and how to fix it.
  • Do not clear all entered information when a validation error occurs.
<label for="email">Email address</label>
<input
  type="email"
  id="email"
  name="email"
  autocomplete="email"
  required
>

<p class="error">
  Error: Enter a valid email address.
</p>
PAGE 26AUDIO AND VIDEO

Audio and Video Accessibility

Audio and video can provide important information, but not every user can access media in the same way.

Recommended Practices

  • Provide synchronized captions for prerecorded video with audio.
  • Provide transcripts when useful.
  • Describe important visual information through an appropriate text or audio alternative.
  • Make media controls accessible through a keyboard.
  • Use clear labels for play, pause, volume, and other controls.

PAGE 27RESPONSIVE ACCESSIBILITY

Responsive and Mobile Accessibility

A responsive interface adapts to different screen sizes and orientations. Users should be able to read content and operate controls on desktops, laptops, tablets, and smartphones.

Desktop
Tablet
Mobile

Responsive Accessibility Practices

  • Use flexible layouts.
  • Keep text readable at different screen sizes.
  • Provide sufficient spacing around controls.
  • Allow users to zoom.
  • Avoid unnecessary horizontal scrolling for ordinary page content at common zoom levels.
  • Test different screen sizes and orientations.
PAGE 28ACCESSIBLE HTML

Accessible HTML Examples

Semantic HTML gives content meaning and helps browsers and assistive technologies understand a webpage. Prefer elements that describe their purpose instead of using generic containers for everything.

Example 1: Semantic Page Structure

<header>
  <h1>Student Services</h1>
</header>

<nav aria-label="Main navigation">
  <a href="index.html">Home</a>
  <a href="services.html">Services</a>
</nav>

<main>
  <h2>Available Services</h2>
  <p>Explore the services offered to students.</p>
</main>

<footer>Copyright 2026</footer>

Example 2: Native Buttons

<button type="button">Open Student Portal</button>
Use native HTML elements whenever possible. ARIA attributes can add missing information when necessary, but they should not replace correct HTML structure.
PAGE 29TESTING AND ACTIVITIES

Testing UI Design and Accessibility

Accessibility should be considered throughout planning, design, development, and testing. Automated tools can find some issues, but they cannot determine whether every page is understandable or easy to use.

A Practical Testing Process

  1. Review page structure, headings, landmarks, lists, and buttons.
  2. Test with a keyboard using Tab, Shift+Tab, Enter, Space, and arrow keys where appropriate.
  3. Check color contrast for text, buttons, icons, and focus indicators.
  4. Inspect images and media for alt text and captions.
  5. Test forms with empty or incorrect values and review error messages.
  6. Resize and zoom the page on mobile-sized screens.
  7. Ask people to try realistic tasks and observe where they hesitate.

Quick Accessibility Checklist

Activity 1: UI Evaluation

Choose a website and identify five interface elements. Explain the purpose of each element and suggest one improvement.

Activity 2: Accessibility Inspection

Navigate a webpage using only your keyboard. Record any button, link, or form control that cannot be reached or activated.

Activity 3: Improve a Form

Create a simple registration form with visible labels, clear instructions, required-field indicators, and helpful error messages.

Hands-On Exercise: Accessible Student Services Page

  1. Create a page with a semantic header, navigation, main section, and footer.
  2. Add a meaningful heading structure.
  3. Include an informative image with alt text.
  4. Create a labeled contact form.
  5. Make all controls keyboard accessible.
  6. Check text contrast and mobile layout.

Expected Output: A simple, usable, and accessible student services webpage.

PAGE 30SUMMARY AND REFERENCES

Lesson Summary

Effective User Interface Design combines clarity, consistency, useful feedback, simplicity, efficiency, and thoughtful visual organization. A good interface helps users understand what they can do and complete tasks confidently.

Accessibility strengthens interface design by removing barriers and supporting different ways of seeing, hearing, understanding, and interacting with content. The POUR principles—Perceivable, Operable, Understandable, and Robust—provide a foundation for accessible web experiences.

Developers should use semantic HTML, meaningful alternative text, readable content, sufficient contrast, keyboard-friendly controls, accessible forms, captions, and responsive layouts.

Key Takeaway: A successful website should not only look good—it should work for as many people as possible.
