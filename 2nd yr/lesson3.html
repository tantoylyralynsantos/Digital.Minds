Processes, Threads, and Process Scheduling

Understand how operating systems manage running programs, execute multiple tasks, and allocate CPU resources efficiently.

📘 Operating Systems ⏱ Learning Module 💻 BSIT
01

Introduction

Modern operating systems are designed to execute multiple programs efficiently while providing users with a responsive and reliable computing environment. To achieve this, operating systems use important concepts such as processes, threads, and process scheduling.

Whenever a user opens a web browser, runs a video player, launches a game, or edits a document, the operating system creates and manages processes and threads. It also schedules processor resources so that running applications receive the CPU time they need.

Key Concepts

  • Process: A program that is currently being executed.
  • Thread: The smallest unit of CPU execution within a process.
  • Process Scheduling: The method used by an operating system to decide which process receives CPU time.
02

Fundamentals of Operating Systems

An operating system is system software that serves as an interface between computer hardware and users. It manages computer resources and provides services that allow applications to run efficiently.

Primary Responsibilities of an Operating System

⚙️

Process Management

Controls running programs and their execution.

🧠

Memory Management

Allocates and manages computer memory.

📁

File Management

Organizes and controls files and folders.

🔌

Device Management

Coordinates connected hardware devices.

🔐

Security Management

Protects system resources and information.

📊

Resource Allocation

Distributes available resources to programs.

Examples of running processes include web browsers, media players, antivirus software, background services, and operating system utilities.

03

Understanding Processes

Definition of a Process

A process is a program that is currently being executed by the computer. A program stored on a disk is passive because it contains instructions and data. When it is loaded into memory and begins execution, it becomes an active entity known as a process.

📄

Program

Microsoft Word stored on a disk. It is not currently running.

→
💻

Process

Microsoft Word currently running on the computer.

Characteristics of a Process

  • Dynamic Nature: A process changes continuously during execution.
  • Resource Ownership: Processes require CPU time, memory, input devices, output devices, and storage.
  • Unique Identity: Every process receives a unique identifier called a Process ID (PID).
  • Execution Context: Each process maintains information about its current instruction, processor registers, memory allocation, and scheduling information.

Importance of Processes

Processes allow operating systems to support multitasking, manage resources efficiently, execute applications concurrently, improve productivity, and maintain system organization.

04

Components of a Process

A process consists of several important memory sections that support program execution.

1. Text Section

Contains the executable instructions that define the actions performed by the program.

Examples: mathematical calculations, data processing, and file operations.

2. Data Section

Stores global variables and static variables used by the application.

Examples: configuration settings, program constants, and shared information.

3. Heap Section

Used for dynamic memory allocation. Memory in the heap is allocated and released during program execution.

Examples: dynamic arrays, linked lists, trees, and data structures.

4. Stack Section

Stores temporary information related to function calls. It commonly contains local variables, return addresses, and function parameters.

The stack follows a Last-In-First-Out (LIFO) structure.

05

Process States

A process moves through several states during its execution. These states help explain how an operating system manages processes.

NEW
→
READY
→
RUNNING
→
TERMINATED

New State

The process is being created. Resources are allocated and process information is initialized.

Ready State

The process is loaded into memory and prepared to execute, but it is waiting for CPU allocation.

Running State

The CPU is actively executing the process instructions.

Waiting State

The process waits for an external event, such as keyboard input, file access, or network communication.

Terminated State

The process has completed execution or has been stopped. Its allocated resources are released.

06

Process Control Block (PCB)

The Process Control Block (PCB) is a data structure maintained by the operating system. It contains information necessary for managing a process and allowing it to resume execution when needed.

PROCESS CONTROL BLOCK

Memory InformationAddress space, allocation
Scheduling InformationPriority, queue information

The PCB stores process identification, process state, program counter, CPU registers, memory information, and scheduling information.

07

Process Operations

Process operations are activities performed on processes throughout their life cycle. The operating system monitors and manages processes from creation to termination.

Common Process Operations

  • Process creation
  • Process execution
  • Process suspension
  • Process resumption
  • Process synchronization
  • Process termination

Process Creation

When a user launches an application or another process creates a new process, the operating system performs several steps:

  1. Assigning a Process Identifier (PID)
  2. Creating the Process Control Block (PCB)
  3. Allocating memory resources
  4. Loading executable code into memory
  5. Initializing CPU registers
  6. Scheduling the process for execution

Parent and Child Processes

A parent process is a process that creates another process. The newly created process is called a child process. For example, a browser may create child processes for tab management, GPU processing, website rendering, and extension execution.

Process Termination

A process may terminate because of normal completion, a user request, a fatal error, or system shutdown. Termination releases resources occupied by the process.

08

Interprocess Communication (IPC)

Interprocess Communication (IPC) is the mechanism through which processes exchange information and coordinate activities. It supports multitasking, data sharing, resource coordination, and process synchronization.

Reasons for IPC

📨

Information Sharing

Processes exchange information, such as a browser communicating with a download manager.

🔗

Resource Sharing

Processes may need access to databases, printers, and storage devices.

⚡

Speed Improvement

Tasks can be divided among processes and executed concurrently.

🧩

Modularity

Applications can be divided into smaller independent processes.

Methods of IPC

Shared Memory

Allows multiple processes to access a common memory area. It supports fast communication and efficient data transfer, but requires synchronization to prevent conflicts.

Message Passing

Processes exchange information through messages. It provides simpler implementation and better isolation, but may introduce communication overhead.

Pipes

Provide a communication channel between related processes. One process sends data while another receives it.

Sockets

Enable communication between processes across networks. They are used in web applications, online games, chat systems, and distributed computing.

09

Understanding Threads

A thread is the smallest unit of CPU execution within a process. While a process represents an entire program, threads represent smaller execution paths within that program.

Processes versus Threads

ProcessThread
Independent execution unitSmaller execution unit
Has its own memory spaceShares memory with threads in the same process
Higher resource consumptionLower resource consumption
Slower creationFaster creation
Greater isolationLess isolation

Example of Threads in a Web Browser

A web browser process may contain threads responsible for:

  • Rendering web pages
  • Downloading files
  • Playing videos
  • Handling user interactions

Components of a Thread

  • Thread Identifier: A unique identification number.
  • Program Counter: Points to the next instruction for execution.
  • Register Set: Stores processor register information.
  • Stack Space: Contains local variables and function call information.

Threads within the same process share process memory, open files, system resources, and security information.

Benefits of Threads

Improved Responsiveness

Applications can remain responsive while background tasks execute.

Resource Sharing

Threads share resources within the same process.

Economy

Creating threads requires fewer resources than creating processes.

Enhanced Parallelism

Threads can execute simultaneously on multicore processors.

10

Types of Threads

User-Level Threads

User-level threads are managed entirely by user applications. The operating system remains unaware of their individual existence.

Advantages: Faster creation, faster switching, and simple implementation.

Disadvantages: Blocking one thread may block the entire process, and parallelism is limited.

Kernel-Level Threads

Kernel-level threads are managed directly by the operating system kernel. The operating system schedules and controls them individually.

Advantages: Better responsiveness, improved parallelism, and greater system support.

Disadvantages: Higher overhead and more complex management.

Hybrid Threading

Hybrid threading combines user-level and kernel-level threads to balance performance, flexibility, and resource utilization.

11

Multithreading Models

A multithreading model defines how user threads are mapped to threads managed by the operating system.

Many-to-One Model

Multiple user-level threads are mapped to a single kernel thread.

Advantages: Fast thread management and low overhead.

Disadvantages: If one thread blocks, all threads block. It also does not provide true parallelism on multiprocessor systems.

One-to-One Model

Every user thread is mapped directly to a kernel thread. The operating system can schedule each thread independently.

Advantages: Better responsiveness and true parallel execution.

Disadvantages: Increased overhead and higher resource consumption.

Many-to-Many Model

Multiple user threads are mapped to multiple kernel threads. The number of user threads can exceed the number of kernel threads.

Advantages: Good resource utilization, improved scalability, and better concurrency.

Disadvantages: More complex implementation and management.

12

Process Scheduling

Process scheduling is the method used by the operating system to decide which process receives CPU time. Since multiple processes compete for processor resources, the operating system must allocate CPU time efficiently.

Objectives of Process Scheduling

  • Maximum CPU Utilization: Keep the processor busy whenever possible.
  • Maximum Throughput: Increase the number of processes completed during a given period.
  • Reduced Waiting Time: Reduce the time a process spends in the ready queue.
  • Faster Response Time: Improve how quickly the system reacts to user requests.
  • Fair Resource Allocation: Give every process a reasonable opportunity to execute.

Scheduling Queues

Job Queue

Contains all processes in the system. Every process enters this queue when created.

Ready Queue

Contains processes loaded into memory that are ready to execute but waiting for CPU allocation.

Device Queue

Contains processes waiting for input/output operations, such as printer, disk, or network operations.

Types of Schedulers

Long-Term Scheduler

Determines which processes enter the system. It handles process admission, workload balancing, and resource planning.

Short-Term Scheduler

Determines which process receives CPU allocation next. It operates frequently and must make decisions quickly.

Medium-Term Scheduler

Temporarily removes processes from memory and later returns them. This process is known as swapping.

Context Switching

A context switch occurs when the CPU changes from executing one process to another. The operating system saves information about the current process and restores the information of the next process.

The saved information may include program counters, CPU registers, process state, memory information, and scheduling information. This information is usually stored in the PCB.

Remember

Context switching enables multitasking and responsiveness, but excessive context switching may reduce performance and increase CPU overhead.

13

Scheduling Criteria

Operating systems evaluate scheduling algorithms using several criteria.

CPU Utilization

Measures the percentage of time the CPU remains active. The objective is to maximize utilization.

Throughput

Measures the number of completed processes during a given period.

Turnaround Time

The total time required from process submission until completion. Lower turnaround times are preferred.

Waiting Time

The amount of time a process spends waiting in the ready queue.

Response Time

Measures how quickly the system responds to requests. Interactive systems prioritize low response times.

Fairness

Scheduling should prevent process starvation and ensure processes receive CPU access.

14

CPU Scheduling Algorithms

Operating systems use different scheduling algorithms to allocate CPU resources.

FCFS

First-Come, First-Served

Processes execute in the order they arrive.

Advantages: Easy implementation and simple operation.

Disadvantages: Long waiting times and poor responsiveness.

Example: If Process A arrives before Process B, Process A executes first.

SJF

Shortest Job First

Selects the process with the shortest execution time.

Advantages: Lower average waiting time and improved efficiency.

Disadvantages: Execution time may be difficult to predict, and starvation may occur.

PRIORITY

Priority Scheduling

Each process receives a priority value. Higher-priority processes execute before lower-priority processes.

Advantages: Important tasks execute earlier and resource allocation is flexible.

Disadvantages: Low-priority processes may experience starvation.

ROUND ROBIN

Round Robin Scheduling

Assigns each process a fixed time slice called a quantum. Processes rotate through the CPU in a circular manner.

Advantages: Fairness, good responsiveness, and suitability for interactive systems.

Disadvantages: Context-switching overhead.

MULTILEVEL QUEUE

Multilevel Queue Scheduling

Divides processes into separate queues according to type, such as system, interactive, and batch processes. Each queue may use a different scheduling algorithm.

Advantages: Organized scheduling and better resource management.

Disadvantages: Complex implementation.

MULTILEVEL FEEDBACK

Multilevel Feedback Queue Scheduling

Allows processes to move between queues. It supports dynamic priority adjustment, improved responsiveness, and adaptability.

Synchronization Concepts

Synchronization is the process of coordinating multiple processes or threads to ensure that shared resources are accessed safely and efficiently. Its primary goal is to maintain data consistency and prevent conflicts.

Race Conditions

A race condition occurs when two or more processes or threads access shared data simultaneously and the final outcome depends on the order of execution.

Example: Bank Account

Initial Balance: ₱10,000

Thread A withdraws ₱2,000.

Thread B withdraws ₱3,000.

A properly synchronized system should produce a final balance of:

₱5,000

Critical Section Problem

A critical section is a portion of program code that accesses shared resources. A correct solution should satisfy three requirements:

  • Mutual Exclusion: Only one process or thread may execute within the critical section at a time.
  • Progress: If no process is inside the critical section, waiting processes should be allowed to proceed.
  • Bounded Waiting: Every waiting process should eventually receive access.

Semaphores

A semaphore is a synchronization tool used to control access to shared resources. It uses operations such as:

Wait Operation

Decreases the semaphore value. If the resource is unavailable, the requesting thread waits.

Signal Operation

Increases the semaphore value to indicate that a resource has become available.

Binary Semaphore: Contains only two possible values, 0 and 1.

Counting Semaphore: Can store multiple values and manage resources available in multiple instances, such as three printers in a laboratory.

Mutex Locks

Mutex stands for Mutual Exclusion. It allows only one thread to access a resource at a time. If a thread acquires the mutex, other threads must wait until the mutex is released.

  1. Thread requests mutex.
  2. Mutex is locked.
  3. Thread enters the critical section.
  4. Thread completes the operation.
  5. Mutex is unlocked.
  6. Other threads may proceed.

Deadlocks and Their Management

A deadlock occurs when two or more processes wait indefinitely for resources held by one another. Because none of the processes can proceed, execution becomes blocked.

Process AHolds Resource 1Waiting for Resource 2
↔ DEADLOCK ↔
Process BHolds Resource 2Waiting for Resource 1

Four Conditions for Deadlock

1. Mutual Exclusion

Resources cannot be shared. Only one process may use a resource at a time.

2. Hold and Wait

A process holds one resource while requesting additional resources.

3. No Preemption

Resources cannot be forcibly removed. They must be released voluntarily.

4. Circular Wait

Processes form a circular chain of resource dependencies, with each process waiting for a resource held by another process.

Deadlock Management

Deadlock Prevention

Attempts to eliminate one or more deadlock conditions through resource restrictions and controlled requests.

Deadlock Avoidance

Evaluates resource requests and grants them only if the system remains in a safe state. One known approach is the Banker's Algorithm.

Deadlock Detection

Allows deadlocks to occur and later identifies them by analyzing resource allocations.

Deadlock Recovery

May involve terminating processes, restarting processes, or reallocating resources.

Real-World Applications

Processes, threads, and scheduling play important roles in modern computing systems.

Web Browsers

Modern web browsers use processes for separate tabs, threads for rendering content, and scheduling for resource management.

Mobile Applications

Smartphones rely on multithreading, process management, and CPU scheduling for music streaming, messaging, and navigation.

Online Banking Systems

Banking systems use processes and threads to manage account access, deposits, withdrawals, and payments. Synchronization helps maintain transaction accuracy.

Cloud Computing

Cloud platforms use process scheduling, thread management, and resource allocation to support many users.

E-Commerce Systems

Online stores process customer requests, orders, payments, and inventory updates concurrently while maintaining accuracy.

Conclusion

Processes, threads, and process scheduling are fundamental concepts in modern operating systems. They enable computers to execute multiple tasks efficiently while maintaining stability, responsiveness, and optimal performance.

Processes serve as the basic units of program execution, while threads provide lightweight mechanisms for performing concurrent tasks within processes. Process scheduling ensures that CPU resources are allocated fairly and effectively among competing tasks.

Synchronization mechanisms such as semaphores and mutexes help maintain data consistency and prevent race conditions. Deadlock management techniques allow operating systems to identify, prevent, avoid, or recover from situations where processes become blocked.

These concepts are applied in web browsers, mobile devices, banking systems, cloud computing platforms, and e-commerce applications.
