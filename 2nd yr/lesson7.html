PAGE 01 • INTRODUCTION

Introduction to Deadlocks and Resource Allocation

Computer processes sharing system resources

Modern operating systems support multiple users, applications, and hardware devices simultaneously. To accomplish this, operating systems must carefully manage resources such as processors, memory, storage devices, printers, network adapters, and input/output devices.

Since resources are limited, multiple processes often compete for the same resources. The operating system must allocate resources fairly and efficiently to maintain system stability and performance.

However, problems may occur when several processes wait indefinitely for resources held by one another. This situation is called a deadlock.

Why is this topic important?

Understanding deadlocks and resource allocation helps explain how operating systems coordinate resources, avoid conflicts, and maintain efficient operation in multitasking environments.

Topics Covered

  • Resource allocation principles and policies
  • Resource allocation graphs and deadlock conditions
  • Deadlock prevention, avoidance, and detection
  • Deadlock recovery and real-world applications
PAGE 02 • FUNDAMENTALS

Fundamentals of Resource Allocation

Operating system assigning resources to processes

What is Resource Allocation?

Resource allocation is the process through which an operating system assigns available resources to processes, users, or applications. Programs need hardware and software components to perform their tasks.

Commonly Allocated Resources

⚙️

CPU Time

Processing time given to programs.

🧠

Memory

RAM used by running applications.

💾

Storage

Space for files and information.

🖨️

Printers

Devices used to print documents.

🌐

Network

Connections for data communication.

⌨️

I/O Devices

Input and output hardware.

Objectives of Resource Allocation

  • Efficient Utilization: Minimize resource waste.
  • Fair Distribution: Provide reasonable access to processes.
  • Improved Performance: Increase throughput and responsiveness.
  • Conflict Prevention: Reduce competition and resource conflicts.
  • System Stability: Maintain reliable operations.
PAGE 03 • SYSTEM RESOURCES

Understanding Resources in Operating Systems

Hardware and software resources

Definition of a Resource

A resource is any hardware or software component required by a process to perform its operations. Processes cannot execute successfully without obtaining the resources they need.

Characteristics of Resources

Limited Availability

A resource exists in a finite quantity. For example, a computer may have only one printer.

Shared Usage

Resources may be shared among multiple processes, such as CPU time.

Allocation Requirement

Processes must request resources before they can use them.

Release Requirement

Resources should be released when they are no longer needed.

Remember: Resource management is important because many processes may need the same limited resources at the same time.
PAGE 04 • CLASSIFICATION

Classification of Resources

Different categories of computer resources

1. Hardware Resources

Hardware resources are the physical components of a computer system.

  • Processors
  • Memory modules
  • Storage devices
  • Printers
  • Network adapters

2. Software Resources

Software resources include programs, data, and operating system services.

  • System files
  • Databases
  • Shared libraries
  • Communication services

3. Reusable Resources

Reusable resources can be used repeatedly by different processes. Examples include CPUs, printers, and storage devices.

4. Consumable Resources

Consumable resources are created and consumed during system operation. Examples include messages, signals, and data packets.

PAGE 05 • ALLOCATION PROCESS

Resource Allocation Concepts

Request, allocation, use, and release of resources

Resource Request

A process submits a request before using a resource. The operating system checks whether the requested resource is available. If it is unavailable, the process may need to wait.

Resource Allocation

When a request is approved, the operating system assigns the resource to the process and updates its allocation records.

Resource Release

After completing its task, the process releases the resource so that other processes can use it.

Resource Sharing

Some resources can be shared among processes. Examples include CPU scheduling, shared memory, and network services.

Basic allocation cycle: Request → Allocation → Use → Release.
PAGE 06 • ALLOCATION POLICIES

Resource Allocation Policies

Different policies for assigning resources

First-Come, First-Served (FCFS)

Resources are allocated according to the order in which requests arrive.

Advantages: Fair and easy to implement.

Disadvantages: May cause delays and lower efficiency.

Priority-Based Allocation

Resources are assigned based on the priority level of each process.

Advantages: Important processes receive resources sooner and critical applications are supported.

Disadvantages: Low-priority processes may experience long delays.

Dynamic Allocation

Resources are assigned according to the current needs of processes.

Advantages: Flexible and can improve utilization.

Disadvantages: More complex to manage.

PAGE 07 • RESOURCE GRAPHS

Resource Allocation Graphs

Process and resource relationships in a graph

Definition

A Resource Allocation Graph (RAG) is a visual representation of relationships between processes and resources. It helps analyze resource usage and identify possible deadlocks.

Components of a Resource Allocation Graph

⭕

Processes

Represented by circles, such as P1 and P2.

▭

Resources

Represented by rectangles, such as R1 and R2.

➡️

Request Edge

P1 → R1 means P1 requests R1.

↪️

Assignment Edge

R1 → P1 means R1 is assigned to P1.

Importance

  • Visualizes resource usage.
  • Helps identify potential deadlocks.
  • Supports operating system analysis.
  • Improves resource management.
PAGE 08 • DEADLOCK INTRODUCTION

Introduction to Deadlocks

Two processes waiting for resources held by each other

What is a Deadlock?

A deadlock occurs when two or more processes cannot continue because each process is waiting for a resource currently held by another process.

Example of a Deadlock

Process A

Holds the printer.

Waiting for the scanner.

Process B

Holds the scanner.

Waiting for the printer.

Neither process can continue because each is waiting for a resource held by the other. Both processes become blocked.

Effects of Deadlocks

  • Reduced system performance
  • Resource wastage
  • Application failures
  • User frustration
  • System unresponsiveness
PAGE 09 • DEADLOCK CONDITIONS

Four Necessary Conditions for Deadlocks

Four conditions that must exist for a deadlock to occur

According to operating system theory, four conditions must be present simultaneously for a deadlock to occur.

1. Mutual Exclusion

A resource can only be used by one process at a time. Example: one printer handling one job at a time.

2. Hold and Wait

A process holds one or more resources while waiting for additional resources.

3. No Preemption

Resources cannot be forcibly removed. The process must release them voluntarily.

4. Circular Wait

Processes form a circular chain where each waits for a resource held by another.

Important: Removing at least one of these four conditions can prevent deadlocks.
PAGE 10 • DEADLOCK MODELS

Introduction to Deadlock Models

Models used to understand process and resource dependencies

Deadlock models represent and analyze situations where processes compete for resources. They help system designers understand how deadlocks occur and how they can be managed.

Common Deadlock Models

  • Single Resource Models: Focus on one type of resource.
  • Multiple Resource Models: Involve several types of resources.
  • Resource Allocation Graph Models: Represent process-resource relationships.
  • State-Based Models: Analyze system states and resource availability.
PAGE 11 • SINGLE RESOURCE

Single-Resource Deadlocks

Processes competing for one resource type

A single-resource deadlock involves processes competing for one type of resource that exists in a limited quantity.

Example

Suppose a system has only one printer. Process A requests the printer while Process B also needs it. If resource requests and releases are improperly managed, waiting dependencies may develop.

Characteristics

  • Limited resource availability
  • Simple dependencies
  • Usually easier to analyze
PAGE 12 • MULTIPLE RESOURCES

Multiple-Resource Deadlocks

Multiple processes waiting for different resources

Multiple-resource deadlocks involve several resource types. These situations are common in modern computing environments.

Example

Process A

Holds Printer

Waits for Scanner

Process B

Holds Scanner

Waits for Storage

Process C

Holds Storage

Waits for Printer

A circular dependency forms because each process waits for a resource held by another process.

Challenges

Multiple-resource deadlocks are more difficult to identify, analyze, resolve, and prevent. Advanced resource management techniques may be required.

PAGE 13 • GRAPH ANALYSIS

Resource Allocation Graphs in Deadlock Analysis

A cycle in a resource allocation graph

A cycle occurs when processes and resources form a closed chain of requests and assignments.

Example of a Cycle

P1 → R1 → P2 → R2 → P1

Single-Instance Resource Systems

If each resource type has only one instance, a cycle in the resource allocation graph guarantees a deadlock.

Multiple-Instance Resource Systems

If resource types have multiple instances, a cycle indicates the possibility of a deadlock, but further analysis is required.

PAGE 14 • PREVENTION

Deadlock Prevention

Preventing deadlocks by eliminating necessary conditions

Deadlock prevention uses techniques that ensure at least one of the four necessary deadlock conditions cannot occur.

Preventing Mutual Exclusion

Make resources shareable whenever possible. Examples include read-only files, network services, and shared memory areas. This is not possible for every resource, such as a printer.

Preventing Hold and Wait

Require processes to request all needed resources at once. This eliminates hold-and-wait but may cause resources to remain unused.

Preventing No Preemption

Allow the system to reclaim resources from a process when necessary, if the resource can safely be reassigned.

Preventing Circular Wait

Assign numerical identifiers to resources and require processes to request resources in ascending order.

PAGE 15 • AVOIDANCE

Deadlock Avoidance

Checking resource requests before granting them

Deadlock avoidance evaluates resource allocation decisions before granting requests. The operating system attempts to ensure that every allocation leaves the system in a safe state.

How Avoidance Works

  • Processes request resources.
  • The operating system examines the request.
  • The system evaluates the possible result of allocation.
  • The request is granted only if the system remains safe.
Deadlock avoidance does not necessarily remove deadlock conditions. Instead, it carefully controls resource allocation to avoid unsafe states.
PAGE 16 • SYSTEM STATES

Safe States and Unsafe States

Safe and unsafe resource allocation states

Safe State

A safe state is a system condition in which there is at least one sequence of process execution that allows all processes to complete successfully.

  • A safe sequence exists.
  • All processes can eventually finish.
  • Resources can be released and reused.

Example of a Safe Sequence

P1 → P3 → P2 → P4

If each process can obtain the resources it needs and release them after completion, the system can remain safe.

Unsafe State

An unsafe state is a condition in which no guaranteed safe sequence exists. It does not automatically mean that a deadlock has already occurred, but it creates a risk of deadlock.

PAGE 17 • BANKER'S ALGORITHM

Banker's Algorithm

Banker's Algorithm evaluates whether a resource request is safe

Definition

Banker's Algorithm is a deadlock avoidance technique that evaluates resource requests before granting them. It determines whether granting a request will leave the system in a safe state.

Why is it Called the Banker's Algorithm?

The idea is similar to how a bank grants loans only when it can still satisfy the needs of its customers. Similarly, an operating system grants resources only when system safety can be maintained.

Data Structures Used

  • Available: Number of currently available resources.
  • Maximum: Maximum resource requirements of each process.
  • Allocation: Resources currently assigned to each process.
  • Need: Additional resources required for completion.

Working Principle

  1. A process requests resources.
  2. The system evaluates the request.
  3. A simulated allocation is performed.
  4. The system checks for a safe sequence.
  5. The request is approved or postponed.

Advantages and Disadvantages

Advantages: Helps prevent deadlocks, maintains safe states, and supports resource planning.

Disadvantages: Requires advance knowledge of maximum resource needs and adds computational overhead.

PAGE 18 • COMPARISON

Deadlock Prevention vs. Avoidance

Comparing two strategies for deadlock management
FeaturePreventionAvoidance
StrategyEliminates at least one deadlock conditionAvoids unsafe states

Both methods are important. Prevention removes conditions that make deadlocks possible, while avoidance evaluates resource requests to keep the system safe.

PAGE 19 • DETECTION

Deadlock Detection

Operating system checking for blocked processes

Deadlock detection is the process used by an operating system to identify whether a deadlock currently exists. Unlike prevention and avoidance, detection allows deadlocks to occur and identifies them afterward.

Why Detection is Necessary

Preventing every possible deadlock may reduce resource utilization. In some environments, such as databases, cloud platforms, and distributed systems, detection may be more practical.

Objectives

  • Identify blocked processes.
  • Detect resource cycles.
  • Support recovery operations.
  • Maintain system stability.
  • Prevent permanent delays.
PAGE 20 • WAIT-FOR GRAPHS

Wait-for Graphs

A wait-for graph showing process dependencies

Definition

A Wait-for Graph (WFG) is a simplified version of a Resource Allocation Graph. It focuses on relationships between processes instead of showing resource nodes separately.

Components

  • Processes: Represented as nodes, such as P1, P2, and P3.
  • Directed Edges: Show that one process is waiting for another.

Example

P1 → P2
P2 → P3
P3 → P1

This circular relationship indicates a deadlock when the graph represents single-instance resource dependencies.

Advantages

  • Simple representation
  • Easy cycle analysis
  • Useful for deadlock detection
PAGE 21 • DETECTION ALGORITHMS

Deadlock Detection Algorithms

Analyzing resource allocation and process requests

Detection algorithms examine system information to determine whether deadlocks exist. They evaluate resource allocation, process requests, available resources, and waiting relationships.

Single-Instance Resource Detection

  1. Create a wait-for graph.
  2. Search the graph for cycles.
  3. Report a deadlock if a cycle exists.

Multiple-Instance Resource Detection

When resources have multiple instances, the system examines current allocations, pending requests, and available resources to determine whether processes can eventually proceed.

Multiple-instance detection requires more detailed analysis because a cycle alone does not always prove a deadlock.
PAGE 22 • RECOVERY

Process Termination

Terminating processes to release locked resources

Process termination is a deadlock recovery method in which one or more processes involved in a deadlock are stopped. Their resources are released so that other processes can continue.

Terminating All Processes

All deadlocked processes are terminated.

Advantages: Simple and fast resolution.

Disadvantages: Significant loss of work and possible data loss.

Terminating One Process at a Time

The operating system terminates processes individually until the deadlock disappears.

Factors include process priority, resource usage, completed work, and restart cost.

PAGE 23 • RESOURCE PREEMPTION

Resource Preemption

Reassigning a resource to help resolve a deadlock

Resource preemption involves temporarily removing resources from processes and assigning them to other processes to break a deadlock.

Steps in Resource Preemption

  1. Resource Selection: Identify resources suitable for reassignment.
  2. Resource Removal: Take selected resources from a process.
  3. Resource Reallocation: Assign resources to waiting processes.
  4. Process Resumption: Allow processes to continue when resources become available.

Advantages

  • May preserve process execution.
  • Reduces workload loss.
  • Provides recovery flexibility.

Disadvantages

  • Increased complexity
  • Additional overhead
  • Possible process delays
PAGE 24 • PROCESS ROLLBACK

Process Rollback

Restoring a process to a previously saved checkpoint

Definition

Rollback restores a process to a previously saved state. The operating system uses checkpoints to recover from deadlocks while reducing the loss of completed work.

Checkpointing

A checkpoint is a saved copy of process information, such as memory contents, register values, and system state information.

Recovery Procedure

  1. Deadlock is detected.
  2. The process is rolled back.
  3. Resources are released.
  4. The process restarts from a checkpoint.

Advantages and Disadvantages

Advantages: Reduces data loss and preserves process progress.

Disadvantages: Requires checkpoint storage and adds system overhead.

PAGE 25 • MODERN OPERATING SYSTEMS

Deadlock Handling in Modern Operating Systems

Modern operating systems managing resources and processes

Windows

Microsoft Windows uses resource management, synchronization mechanisms, and timeout strategies. Many deadlock risks are reduced through system design.

Linux

Linux provides tools for resource monitoring, process tracking, and lock management. Developers use these tools to minimize deadlock risks.

macOS

macOS combines resource management, synchronization controls, and process scheduling to reduce deadlock occurrences.

Modern operating systems generally combine multiple techniques instead of relying on only one deadlock management method.
PAGE 26 • DISTRIBUTED SYSTEMS

Distributed System Deadlocks

Processes and resources across connected computers

Definition

Distributed deadlocks occur when processes in different computers wait for resources controlled by other computers in a distributed system.

Characteristics

  • Multiple servers
  • Network communication
  • Shared services
  • Remote resources

Challenges

  • Resource information is distributed.
  • Communication delays may occur.
  • System states change frequently.

Specialized detection algorithms are needed because resource information is not always available in one central location.

Time-sensitive systems requiring predictable resource allocation

Real-time systems require predictable and timely resource allocation. Delays may affect critical operations and system safety.

PAGE 28 • STARVATION

Resource Starvation and Deadlock Management

A low-priority process waiting repeatedly for resources

What is Resource Starvation?

Resource starvation occurs when a process waits indefinitely because resources are continually allocated to other processes.

Causes of Starvation

  • Priority scheduling
  • Resource monopolization
  • Poor allocation policies

Prevention Techniques

  • Aging: Gradually increase the priority of waiting processes.
  • Fair Scheduling: Give processes reasonable access to resources.
  • Priority Adjustments: Adjust priorities to reduce indefinite waiting.

Real-World Applications of Deadlocks and Resource Allocation

Resource management in real-world computing environments

Conclusion

Deadlocks and resource allocation are fundamental concepts in operating system design. Resource allocation ensures that processes receive the hardware and software resources necessary to execute efficiently, while deadlock management prevents situations in which processes become permanently blocked.

This lesson discussed computing resources, allocation strategies, resource allocation graphs, deadlock conditions, prevention, avoidance, detection, and recovery. It also explored real-world applications in databases, banking, cloud computing, distributed systems, industrial automation, and healthcare.

As computing environments continue to evolve through artificial intelligence, virtualization, cloud computing, and the Internet of Things, effective resource allocation and deadlock management remain essential for reliable and stable systems.
