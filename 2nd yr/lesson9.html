1. Introduction to Web Security

Web security refers to the practices, technologies, and procedures used to protect websites, web applications, servers, and user information from unauthorized access, attacks, and other online threats.

As more organizations use websites to provide services, store records, process payments, and communicate with customers, protecting digital information has become increasingly important.

Web developers must consider security throughout the development process. A website should not only look attractive and function correctly; it should also protect the people who use it.

Why Is Web Security Important?

  • Protects personal and confidential information.
  • Prevents unauthorized access to user accounts.
  • Reduces the risk of data theft and financial loss.
  • Maintains the trust and confidence of website visitors.
  • Helps organizations maintain reliable online services.
Real-World Example

When a user logs in to an online banking website, security measures help ensure that only the authorized account owner can access financial information and perform transactions.

PAGE 02

2. Fundamentals of Web Security

Web security is based on several important principles that help protect information and systems. These principles guide developers when designing and maintaining secure applications.

The CIA Triad

Confidentiality

Ensures that sensitive information is accessible only to authorized individuals.

Integrity

Ensures that information remains accurate and is not changed without permission.

Availability

Ensures that systems and information are accessible when authorized users need them.

Other Security Principles

  • Authentication: Verifying the identity of a user.
  • Authorization: Determining what an authenticated user can access.
  • Accountability: Recording activities so actions can be reviewed.
  • Least Privilege: Giving users only the permissions required for their tasks.
Important Concept

A secure website combines confidentiality, integrity, and availability to protect both its users and its information.

3. Understanding Authentication

Authentication is the process of verifying the identity of a person, device, or system before allowing access to a protected resource.

Websites commonly authenticate users through usernames and passwords. More advanced systems may also use verification codes, biometric information, security keys, or authentication applications.

Common Authentication Factors

  1. Something You Know: Passwords, PINs, or security answers.
  2. Something You Have: A smartphone, security token, or hardware key.
  3. Something You Are: Fingerprints, facial recognition, or other biometric characteristics.

How Authentication Works

  1. The user opens a protected website.
  2. The website displays a login form.
  3. The user submits their credentials.
  4. The server checks the submitted information.
  5. If the identity is verified, the user can proceed.
Example

A student enters their school email and password into a learning management system. The system verifies the credentials before opening the student's account.

4. Understanding Authorization

Authorization is the process of determining what an authenticated user is allowed to do within a website or application.

After a system confirms a user's identity, it checks the permissions assigned to that account. These permissions determine which pages, files, features, and actions the user can access.

Examples of Authorization

  • An administrator can create, update, and delete user accounts.
  • A teacher can manage class records and learning materials.
  • A student can view their grades and personal information.
  • A regular customer can view and manage their own orders.

Why Authorization Matters

Without proper authorization, users may gain access to information or functions that should be restricted. This can lead to data exposure, unauthorized changes, and misuse of the system.

Example

A student may successfully log in to a school portal, but the student should not be allowed to open the administrator dashboard or modify another student's grades.

5. Authentication vs. Authorization

Authentication and authorization are related security processes, but they serve different purposes.

Authentication Authorization
Verifies who the user is. Determines what the user can do.
Usually happens first. Usually follows authentication.
Uses passwords, codes, or biometrics. Uses permissions, roles, and access policies.
Answers: "Who are you?" Answers: "What are you allowed to access?"

Example in a School Website

Authentication confirms that a person is a registered student. Authorization determines whether that student can view their own grades, submit assignments, or access restricted administrative features.

Remember

Authentication verifies identity, while authorization controls access.

6. Password Security

Passwords are one of the most widely used methods of authentication. They protect user accounts by requiring a secret combination of characters before access is granted.

Characteristics of a Strong Password

  • Uses sufficient length.
  • Combines different types of characters when appropriate.
  • Avoids common words and predictable patterns.
  • Does not include easily guessed personal details.
  • Is unique for each important account.

Common Password Mistakes

  • Using the same password on multiple websites.
  • Sharing passwords with other people.
  • Using simple passwords such as 123456.
  • Writing passwords in publicly accessible locations.
  • Ignoring security warnings after a possible account compromise.
Security Tip

Use a reputable password manager to create and store unique passwords for different accounts.

7. Password Hashing and Storage

Web applications should never store users' passwords as plain text. If a database is exposed, plain-text passwords can be read immediately by anyone who obtains the database.

Password hashing transforms a password into a fixed-length output using a one-way cryptographic function. A secure password-storage system uses a dedicated password-hashing algorithm with a unique salt for each password.

Important Terms

  • Hashing: A one-way process that transforms input into a hash value.
  • Salt: Random data added to a password before hashing.
  • Password Verification: Checking a submitted password against the stored password hash.

Recommended Password-Hashing Algorithms

  • Argon2id
  • bcrypt
  • scrypt
Important

Fast general-purpose hashes such as MD5 and SHA-1 should not be used alone for password storage.

8. Multi-Factor Authentication

Multi-Factor Authentication (MFA) is a security method that requires users to provide two or more different verification factors before accessing an account.

Common MFA Methods

  • One-time passwords sent through an approved channel.
  • Authenticator applications.
  • Hardware security keys.
  • Fingerprint or facial verification.
  • Passkeys using supported devices.

Benefits of MFA

  • Provides additional protection beyond passwords.
  • Makes stolen passwords less useful to attackers.
  • Helps protect sensitive accounts.
  • Reduces the risk of unauthorized login attempts.
Example

A user enters their password and then confirms the login using an authenticator application. Both steps help verify the user's identity.

9. Sessions and Cookies

Sessions and cookies help websites maintain information about a user's interaction across multiple requests.

What Is a Session?

A session is a period of interaction between a user and a web application. After a successful login, the server may create a session to remember that the user has been authenticated.

What Is a Cookie?

A cookie is a small piece of data stored by a browser. Websites may use cookies to maintain sessions, remember preferences, or support other website functions.

Important Cookie Security Attributes

  • HttpOnly: Helps prevent JavaScript from reading a cookie.
  • Secure: Restricts cookie transmission to secure HTTPS connections.
  • SameSite: Helps control when cookies are sent with cross-site requests.
Example

When a user logs in to an online shopping website, a session may keep the user signed in while browsing different product pages.

10. Authentication Tokens

An authentication token is a digital credential used to represent an authenticated user or authorize access to a protected resource.

Tokens are commonly used in web applications and APIs. Instead of repeatedly submitting a username and password, a client may send a valid token with requests.

JSON Web Token (JWT)

JSON Web Token is a compact format for representing claims between parties. A signed JWT can help a server verify that its contents have not been changed.

Token Security Practices

  • Transmit tokens only through HTTPS.
  • Protect tokens from unauthorized access.
  • Use suitable expiration periods.
  • Validate signatures and relevant claims.
  • Provide a process for revoking or replacing compromised tokens.
Example

A mobile application may send an access token when requesting a user's profile from a protected API.

11. Access Control Models

Access control refers to the rules and mechanisms used to decide who can access particular resources and what actions they can perform.

Common Access Control Models

DAC

Discretionary Access Control allows resource owners to decide who can access their resources.

MAC

Mandatory Access Control uses centrally defined security classifications and policies.

RBAC

Role-Based Access Control assigns permissions based on a user's role.

ABAC

Attribute-Based Access Control makes decisions using attributes of users, resources, and context.

Example

A school system may give administrators access to student management tools while students can only access their own academic records.

PAGE 12

12. Role-Based Access Control

Role-Based Access Control (RBAC) is a method of managing permissions by assigning users to roles. Each role is associated with a specific set of allowed actions.

Sample Roles in a School System

  • Administrator: Manages accounts, settings, and system records.
  • Teacher: Manages classes, assignments, and student performance.
  • Student: Views lessons, submits activities, and checks grades.
  • Guest: Views only publicly available information.

Advantages of RBAC

  • Makes permission management easier.
  • Reduces unnecessary access.
  • Supports organized account administration.
  • Helps enforce the principle of least privilege.
Example

When a teacher is assigned the Teacher role, the application grants the permissions associated with that role instead of manually configuring every permission separately.

13. Data Encryption

Encryption is the process of converting readable information, called plaintext, into an unreadable form, called ciphertext, using a cryptographic method and key.

Types of Encryption

  • Symmetric Encryption: Uses the same secret key for encryption and decryption.
  • Asymmetric Encryption: Uses a public key and a corresponding private key.

Why Encryption Is Important

  • Protects sensitive information during transmission.
  • Helps secure stored information.
  • Reduces the impact of unauthorized data exposure.
  • Supports secure communication between systems.
Example

When a user submits sensitive information through an HTTPS website, encryption helps protect the information while it travels between the browser and server.

14. HTTPS and SSL/TLS

HTTPS stands for Hypertext Transfer Protocol Secure. It protects communication between a web browser and a web server by using Transport Layer Security (TLS).

TLS provides encryption, integrity protection, and server authentication through digital certificates and cryptographic protocols.

HTTPS Benefits

  • Protects information from being easily read during transmission.
  • Helps detect unauthorized modification of transmitted data.
  • Helps users verify the identity of the website they connect to.
  • Supports safer online transactions and account logins.

HTTP vs. HTTPS

HTTPHTTPS
Does not provide TLS protection by itself.Uses TLS to protect communication.
Does not encrypt traffic by default.Encrypts data in transit.
Not suitable for sensitive information without another secure layer.Recommended for websites, especially those handling accounts or personal data.
Remember

Modern websites should use HTTPS throughout the site, not only on the login page.

15. Common Web Security Attacks

Web applications may be targeted by attackers who attempt to steal information, interrupt services, or gain unauthorized access.

Examples of Web Security Threats

  • Phishing: Tricking users into revealing sensitive information through fake messages or websites.
  • Malware: Malicious software designed to damage systems or steal information.
  • SQL Injection: Inserting malicious SQL input into an application.
  • Cross-Site Scripting: Injecting malicious scripts into pages viewed by other users.
  • Cross-Site Request Forgery: Tricking an authenticated browser into making an unwanted request.
  • Denial-of-Service: Overwhelming a service so legitimate users cannot access it.
Security Awareness

Understanding common attacks helps developers identify weaknesses and apply appropriate protection before attackers exploit them.

PAGE 16

16. SQL Injection

SQL Injection is a security vulnerability that occurs when an application includes untrusted input in database queries without proper handling.

An attacker may attempt to change the meaning of a query, access unauthorized records, or modify database information.

How to Prevent SQL Injection

  • Use parameterized queries or prepared statements.
  • Avoid building SQL statements through unsafe string concatenation.
  • Validate input according to the expected data type and format.
  • Use database accounts with limited permissions.
  • Handle database errors without revealing sensitive technical details.

Secure Development Example

A login system should pass a submitted username as a query parameter rather than directly combining it with SQL command text.

Important

Input validation is useful, but parameterized queries are a primary defense against SQL injection.

PAGE 17

17. Cross-Site Scripting (XSS)

Cross-Site Scripting is a vulnerability that allows an attacker to cause malicious scripts to run in another user's browser through a vulnerable website.

Types of XSS

  • Stored XSS: Malicious content is stored by the application and later displayed to users.
  • Reflected XSS: Malicious input is immediately included in a response page.
  • DOM-Based XSS: Client-side JavaScript handles untrusted data in an unsafe way.

Ways to Prevent XSS

  • Encode output according to its context.
  • Avoid inserting untrusted content as executable HTML.
  • Use safe DOM methods such as textContent when displaying plain text.
  • Apply a suitable Content Security Policy.
  • Sanitize HTML when user-generated HTML must be supported.
Example

A comment section should display user-submitted text safely instead of treating the content as executable code.

PAGE 18

18. Cross-Site Request Forgery (CSRF)

Cross-Site Request Forgery is an attack that tricks a user's browser into sending an unwanted request to a website where the user is already authenticated.

If the website does not properly protect sensitive actions, the request may be processed using the user's existing session.

Possible Consequences

  • Unauthorized changes to account settings.
  • Unwanted updates to personal information.
  • Unauthorized actions performed using a user's account.

Prevention Methods

  • Use anti-CSRF tokens for state-changing requests.
  • Configure appropriate SameSite cookie attributes.
  • Verify request origins where appropriate.
  • Require re-authentication for highly sensitive operations.
  • Do not use GET requests for actions that change important data.
Example

A secure banking application should verify that a money-transfer request genuinely originated from its own trusted application flow.

19. Brute-Force and Credential Attacks

A brute-force attack involves repeatedly attempting different passwords or credentials until the correct combination is found.

Credential stuffing is another attack in which previously exposed username and password combinations are tested against other websites.

Protection Strategies

  • Apply rate limiting to login attempts.
  • Use multi-factor authentication.
  • Monitor suspicious login activity.
  • Use secure password-storage methods.
  • Notify users about unusual account activity.
  • Use carefully designed temporary account protections.
Example

If a login system detects many failed attempts from one source, it can slow down or temporarily restrict further attempts and record the activity for review.

20. Secure Coding Practices

Secure coding means developing software in a way that reduces security weaknesses and protects information from misuse.

Important Secure Coding Practices

  • Validate all untrusted input.
  • Encode output before displaying untrusted data.
  • Use prepared statements for database queries.
  • Protect sensitive operations with authorization checks.
  • Use secure authentication and session management.
  • Avoid exposing passwords, keys, and private information in source code.
  • Keep libraries and frameworks updated.
  • Review code for security problems before deployment.
Developer Reminder

Security should be considered from the planning stage through development, testing, deployment, and maintenance.

21. Database Security

Database security involves protecting stored information against unauthorized access, accidental loss, improper modification, and data theft.

Database Protection Methods

  • Require authentication for database access.
  • Assign limited permissions to database accounts.
  • Encrypt sensitive information when appropriate.
  • Back up important data regularly.
  • Monitor database activity.
  • Use secure connections between applications and databases.
  • Remove unused accounts and permissions.

Why Backups Matter

Backups provide a way to restore information after accidental deletion, system failure, ransomware incidents, or other data-loss events.

Example

An online school portal should protect student records and maintain secure backups so important academic information can be recovered when necessary.

22. API Security

An Application Programming Interface (API) allows different software systems to communicate and exchange information. APIs often provide access to sensitive data, making security essential.

Common API Security Measures

  • Require authentication for protected endpoints.
  • Check authorization for every sensitive operation.
  • Validate request data.
  • Use HTTPS.
  • Apply rate limiting.
  • Protect API keys and access tokens.
  • Return only the information a client is permitted to receive.

API Authentication Methods

Depending on the application, APIs may use OAuth 2.0, access tokens, signed requests, or other suitable authentication mechanisms.

Example

A mobile application requests a student's class schedule through an API. The API must verify the user's identity and permission before returning the schedule.

23. Data Privacy and User Protection

Data privacy concerns how personal information is collected, used, stored, shared, and protected by organizations and applications.

Examples of Personal Information

  • Full name and contact information.
  • Email addresses and account identifiers.
  • Location information.
  • Financial and transaction details.
  • Educational and employment records.

Privacy Protection Practices

  • Collect only information that is necessary.
  • Explain how personal information will be used.
  • Restrict access to authorized personnel.
  • Use appropriate security controls.
  • Follow applicable privacy laws and organizational policies.
  • Dispose of information securely when it is no longer needed and retention rules permit.
Important

In the Philippines, organizations handling personal data should understand and comply with the Data Privacy Act of 2012 and applicable regulations.

PAGE 24

24. Web Security Best Practices

Maintaining a secure website requires a combination of technical controls, good development practices, and responsible user behavior.

Recommended Practices

  1. Use HTTPS across the website.
  2. Store passwords using a dedicated password-hashing algorithm.
  3. Enable MFA for important accounts.
  4. Use secure session and cookie settings.
  5. Validate input and encode output.
  6. Use least-privilege permissions.
  7. Keep software and dependencies updated.
  8. Perform regular security testing.
  9. Back up important information.
  10. Monitor and investigate suspicious activity.
Key Point

No single security feature can protect every website. Effective protection requires multiple layers of security.

25. Security Monitoring and Logging

Security monitoring is the continuous observation of systems, applications, and network activity to identify suspicious behavior and possible security incidents.

Examples of Activities to Monitor

  • Repeated failed login attempts.
  • Unexpected account permission changes.
  • Unusual access to sensitive records.
  • Unexpected system configuration changes.
  • Suspicious API requests.

What Is a Security Log?

A security log is a record of important system events. Logs can help administrators investigate incidents, identify patterns, and understand what happened during a security event.

Example

A website administrator reviews login logs after receiving an alert about repeated unsuccessful attempts to access an account.

PAGE 26

26. Security Incident Response

A security incident is an event that threatens the confidentiality, integrity, or availability of information or systems.

Basic Incident Response Activities

  1. Preparation: Create policies, procedures, and response plans.
  2. Detection: Identify suspicious activities or possible incidents.
  3. Containment: Limit the incident's impact.
  4. Eradication: Remove the cause of the incident.
  5. Recovery: Restore affected systems safely.
  6. Lessons Learned: Review the incident and improve security controls.

Why Incident Response Is Important

A prepared response helps organizations reduce damage, restore services, protect users, and improve their security practices.

Example

If an administrator discovers a compromised account, the organization may disable the affected credentials, investigate the activity, reset access, and review related logs.

29. Glossary of Terms

Authentication: The process of verifying a user's identity.

Authorization: The process of deciding what an authenticated user can access.

Encryption: Transforming readable data into protected, unreadable data.

Hashing: Transforming input into a hash value using a one-way function.

Multi-Factor Authentication: Using two or more different authentication factors.

HTTPS: A secure version of HTTP that uses TLS.

Cookie: A small piece of data stored by a browser.

Session: A period of interaction between a user and an application.

SQL Injection: An attack that manipulates database queries through unsafe input handling.

Cross-Site Scripting: A vulnerability involving malicious scripts executed in users' browsers.

CSRF: An attack that causes an authenticated browser to send an unwanted request.

Firewall: A security control that filters network traffic according to rules.

Access Control: Rules that determine who can use a resource.

Token: A digital credential used to represent authorization or authentication.

Data Privacy: The proper handling and protection of personal information.

30. Conclusion and References

Lesson Summary

Authentication, authorization, and web security are essential parts of developing reliable and trustworthy websites. Authentication verifies the identity of users, while authorization determines which resources and actions they are allowed to access.

Developers must also understand password security, hashing, encryption, sessions, tokens, access control, and common web attacks. Applying secure coding practices and monitoring systems helps reduce the risk of unauthorized access and data exposure.

By following security best practices, web developers can build applications that protect user information and provide safer online experiences.

Final Learning Reminder

Security is not a one-time task. It is an ongoing responsibility throughout the life of a web application.
